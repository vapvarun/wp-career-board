## G3 - Reviewed diff (v1.8.0..HEAD, 82 PHP files)

### Fixed

- **LOW, core REST meta write (`modules/jobs/class-jobs-meta.php`).**
  - Exposure: a user who could edit their own job through `/wp/v2/wcb_job` (an employer who is also an Author) could set `_wcb_featured`, move `_wcb_board_id` without paying, or put the job under another company (`_wcb_company_id`).
  - Fix: those keys, and `_wcb_company_name`, now need `wcb/manage-settings` through core REST. The wcb/v1 routes keep writing them under their own ownership and payment checks.
  - Probe: employer+author was 200 with `featured=1` on the old code, 403 with nothing written now. Admin 200.
  - Not reachable by `wcb_employer` or `wcb_candidate` alone, since they have no `edit_posts`.

### Accepted (cards in Bugs)

- **LOW, linked-company user meta (`EmployersModule::owned_companies()`).**
  - Issue: the company in the user's `_wcb_company_id` counts as owned without an authorship check.
  - Why accepted: no member path writes it to a company the user doesn't own. Register, create, set main, delete, the wizard and the importer were all traced.
  - Why it stays: it is how employers reach a company an admin created for them. Owner decision on clearing stale links is pending.
- **LOW, proxy-chain IP (`AppCredentials::client_ip()`).**
  - Right-most hop is correct for one trusted proxy.
  - Behind a CDN plus a load balancer with `X-Forwarded-For`, every visitor shares one rate-limit bucket. This is availability, not a bypass.
  - Help text or a hop-count filter will follow.
- **MEDIUM (from the Pro review, code in Free), present since 1.8.0.**
  - Two concurrent board moves can leave a job on the dearer board at the cheaper price, because the board write and restore in `JobsEndpoint` run outside the SDK item lock.
  - Reachable by an employer or co-owner, not a candidate.

### Scanner-visible but safe (new or changed this cycle)

- `get_my_applications`, `dashboard_counts` (`awaiting_apps`, `new_apps`, `jobs_with_apps`), `get_my_jobs`, `company_cards`: every query is built on `job_scope_sql()` / `applications_scope_sql()` for the current user, prepared, with `requested_company()` refusing a company the user doesn't run.
- `/employers/{id}/main` and `DELETE /employers/{id}`: owned-and-live check; delete is creator or admin only, to trash.
- Public `GET /employers/{id}/jobs`: strips `appCount`/`appLabel` for non-owners (closes a 1.8.0 count leak).
- `owns_job()` replacing `post_author` checks: each site still also gated by its ability.
- `CompanyMetaShape::types()` / `type_slug()`: fixed allowlist, unknown values become `''`.
- `CandidatesModule::public_name()`: never a login or email; escaped where printed.
- `Text::dash_lists()`: display only, both callers wrap in `wp_kses_post`.
- `DashboardTabs::print_guard()`: values through `wp_json_encode`, printed with `wp_print_inline_script_tag`.
- Changed `view.js` / modules: no `innerHTML`, `insertAdjacentHTML` or `data-wp-html` added.
- Guest apply: an existing account's email gets 409 (accepted enumeration, owner decision, same as lost-password); repeat applies answer like first ones; private profiles answer 404.
