## Behaviour changes with a security angle

- **Content capabilities.** Jobs, applications, companies, resumes and boards use their own `capability_type` with `map_meta_cap`; only administrators get the new caps (`Roles::add_admin_caps()`, one `wp_user_roles` write). Editors, Authors and Contributors can no longer create, edit, publish or delete them through `/wp/v2` or wp-admin. Uninstall removes the caps. Test: `tests/test-cpt-capabilities.php`.
- **Withdrawn applications.** CV download (`PrivateFiles::is_party_to_application()` excludes withdrawn for the employer side), CSV export, every employer list and the single application hide the candidate's email, letter, answers, CV links, resume id and AI summary.
- **Trashed applications.** Every write is refused for non-admins; status changes and Pro stage moves answer 409 `wcb_application_trashed` for everyone, admins included (`ApplicationLifecycle::transition()` refuses too). Test: `tests/test-trashed-application-writes.php`.
- **Co-owners.** Add, remove and search are creator-or-admin (`delete_item_permissions_check`); listing is anyone who runs the company. Targets must hold `wcb_post_jobs`, at most 20, the creator cannot be removed (409). Company routes answer 404 `wcb_company_not_found` for an id that is not a company; before, an admin passed `update_item_permissions_check` for any post id. The wp-admin box adds through REST (`wp.apiFetch`, core nonce) and writes text with `textContent`.
- **Job views.** One view per visitor per job an hour, checked with one prepared indexed query; visitors are an HMAC with `wp_salt('auth')`.
- **Install.** The 1.5.0 upgrade's transient cleanup is one prepared `DELETE` with `esc_like`.

## Scanner-visible but safe (new in this diff)

- `core/class-install.php` raw `$wpdb->query` DELETE: prepared, constant prefixes, `esc_like`.
- `api/class-rest-controller.php` raw SELECT in `record_job_view()`: prepared, indexed by `job_visitor`.
- `api/endpoints/class-employers-endpoint.php` IN-list `prepare()`: placeholders from `array_fill`, values from a fixed list or `sanitize_key`.
- `admin/class-admin-meta-boxes.php` inline script on `wp-api-fetch`: data is `wp_json_encode` of an int and i18n strings; calls `/wp/v2/users?context=edit`, which needs `list_users`, on a screen only admins open.
- `wcb_owner_error` read from `$_GET`: shown only through a fixed message list keyed by `sanitize_key`.
- `Icon::svg()` echoes with `phpcs:ignore`: fixed SVGs from the helper.

## Not covered

Runtime of the review itself (it was static; the fixes carry tests), email templates, GDPR export/erase paths, and multisite beyond reading the code.
