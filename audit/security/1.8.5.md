## Behaviour changes with a security angle

- **Private CV access.** `PrivateFiles::is_party_to_application()` is one `LIMIT 1` query and ignores trashed and auto-draft applications, so a trashed application no longer grants a download, and the check no longer reads only the newest 100 applications. Tests: `tests/test-private-file-access-scale.php`.
- **Visitor IP.** `AppCredentials::client_ip_hash()` stores a keyed hash (HMAC with the site salt), not a plain or unkeyed hash. Test: `tests/test-ip-hash-keyed.php`.
- **Guest apply.** A guest application counts against the hourly limit before its answers are read, and the multi-choice answer splitter is bounded.
- **Job expiry length.** Held to 1-365 days in the schema and the setup wizard.
- **Admin scripts.** Use `wp.apiFetch` (nonce and root from core) instead of hand-built fetch calls.
- **Public writes (e28f7128).** A save for an id that is not a published job or company is refused with 404, so a member can no longer write rows for ids that do not exist (removing a save always works). The view route records one row per visitor and job an hour through the existing hourly limiter, so a script cannot grow `wcb_job_views` or inflate counts. Both sign-up routes run the per-IP sign-up limit before the existing-email check, so the 409 is no longer a free probe; the 409 message is unchanged by owner decision. Tests: `tests/test-rest-write-hardening.php`, `tests/test-bookmark-state.php`.
- **Viewer state in a shared list (e28f7128, 83360b9a).** The companies list is cached for everyone; `is_bookmarked` is added after the cache read, per viewer, from that user's own meta, and the response varies on `Cookie, Authorization`. A second member is never shown the first one's saves (tested). The list reads send the REST nonce so the server knows the member.
- **Review note.** G3 for these changes is the author's own review, not independent.
