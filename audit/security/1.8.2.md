## G3 - Reviewed diff (v1.8.1..HEAD, 110 files)

### Fixed

- **Guest job page carried other members' resumes (present since 1.0.0), commit 3df10af.**
  - Exposure: `blocks/job-single/render.php` queried resumes with `'author' => $current_user_id`. For a guest that is 0, which WordPress reads as any author, so every guest job page put up to 20 published resumes from any member (id, title, has PDF) into the interactivity state, private ones included.
  - Fix: no resume query for user 0. The same class (`'author' =>` with a possible 0) was swept across Free and Pro: every other block returns early for a guest, and Pro's `list_resumes()` / `count_resumes()` now do too (Pro a9ca0ba).

### 1.8.1 accepted items

- **LOW, linked-company user meta: fixed** in f5f8066. A stale `_wcb_company_id` is cleared when a company passes to another author, a co-owner is removed, or a user is deleted with reassignment (owner decision). Probed: after the author changed, the old employer's link was gone and their PUT on the company answered 403.
- **LOW, proxy-chain IP: fixed** in 8eac42b. New `wcb_client_ip_trusted_hops` filter (clamped to at least 1), and the anti-spam help text recommends the CDN's own header. The default is unchanged.
- **MEDIUM, concurrent board moves: fixed** in c826006. `JobsEndpoint` takes a per-job `GET_LOCK`, reads the old board inside it and releases it in `finally`; a failed lock answers 409 before any write. Covered by Pro `tests/test-board-move-concurrency.php`.

### Scanner-visible but safe (new or changed this cycle)

- Required title, salary range and required custom fields: ownership is checked before validation (a second employer gets 403), and every refusal runs before the first write. Probed on fixtures: empty title 400 `wcb_missing_title`, minimum above the stored maximum 400 `wcb_salary_range`, nothing written.
- `ApplicationNotes::can_delete`: only the note's author (user above 0) or `wcb/manage-settings`; otherwise 404. The route keeps `update_permissions_check`.
- Admin Trash restore and delete permanently: list nonce plus post type check plus `wcb/manage-settings` and `edit_post` / `delete_post` on each post. Suspended and Banned views are read-only queries; redirects go through `add_query_arg` and `wp_safe_redirect`.
- `ListEmptyState` chips and the `author` / `candidate_id` list filters: `absint` / `sanitize_text_field` in, `esc_*` out, admin only.
- Email locale: `_wcb_guest_locale` comes from `determine_locale()` on the server, never from the request. Template folders come from the theme and the developer filter `wcb_email_template_dirs`.
- Upgrade SQL (DB 1.3.9 to 1.4.2) and the job search currency clauses: constants and `prepare()`.
- CV upload: `PrivateFiles::CV_MIMES` drives both the MIME allowlist and the `wp_handle_upload` override; the allowed types are unchanged.
- WPJM import: `JobsMeta::parse_amount()` uses a strict pattern and returns null otherwise; admin path.
- `ApplicationsCsv::cell()`: CSV formula neutralising, now shared with Pro's credits export.
- Renders: new `data-wp-context` values are literals or `esc_attr( wp_json_encode() )`; no `innerHTML`, `insertAdjacentHTML` or `data-wp-html` added in JS; the Turnstile panel is built with `createElement` / `textContent`.
- Emails tab: one form, still `wcb_email_settings_save` nonce plus `wcb/manage-settings`, bodies through `wp_kses_post`.
