# WP Career Board 1.8.4 - Security notes

Branch `1.8.4`, a bug-fix release on `v1.8.3`. Pro has its own record in `wp-career-board-pro/audit/security/1.8.4.md`. The full Gate G review (sweep, route authority, diff review) is added to this file at release.

## Plugin Check

- **Fixed: `admin/class-admin-applications.php` PreparedSQL (3 errors).** The job-title half of the Applications search interpolated the title clause and the ID cap inside the `get_col()` call, and the ignore on the call line did not reach the next two lines. The query is now built in `$sql` and the existing ignore on the `get_col( $sql )` line covers it. `$title_clause` comes from `TitleSearch::title_clause()`, which already runs `$wpdb->prepare()`, so it is not prepared twice; the cap is an int constant. Ignore budget unchanged (prepared-sql 22). Check: `vendor/bin/phpcs --standard=WordPress --sniffs=WordPress.DB.PreparedSQL admin/class-admin-applications.php` reports 0 (3 before).
- **Accepted: Cloudflare Turnstile, 4 x `OffloadedContent`.** `modules/antispam/class-turnstile-driver.php` and the setup wizard's anti-spam step load `https://challenges.cloudflare.com/turnstile/v0/api.js`. Cloudflare requires the widget script to load from its own CDN (a bundled copy is not supported and would stop receiving token changes), so this stays. It only loads when the site owner picks Turnstile as the anti-spam provider.

## Behaviour changes with a security angle

- **Multisite registration follows the network setting.** Both sign-up routes, the Employer Registration block and the dashboard gate's "Create an account" no longer bypass `users_can_register` on multisite. Core reads that option from the network Registration setting there, so a subsite where visitors could register while the network said "Registration is disabled" now refuses them (403 `wcb_registration_disabled`). Sites that relied on the old behaviour need the network admin to allow user accounts. Closes the 1.8.3 accepted LOW "Multisite registration (old code)".
- **Job form drafts are cleared on logout.** An explicit logout sets `wcb_clear_drafts` (value: the blog ID, one minute, path `/`, `SameSite=Lax`, `Secure` on HTTPS, not HttpOnly because the page script must read and expire it). It carries no user data. While it is present, `assets/js/wcb-clear-drafts.js` loads on the sign-in screen or the next front-end page and removes that site's `wcb-job-draft-*` and `wcb-job-draft-simple-*` localStorage keys. A session that only expires keeps its draft. Residual risk: if the logout redirect lands on a page served from a full-page cache, the script runs on the next uncached page instead; the default redirect is the uncached sign-in screen. Closes the 1.8.3 accepted LOW "Job form draft stays in localStorage after logout".
