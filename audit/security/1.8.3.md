## G3 - Reviewed diff (v1.8.2..HEAD)

### Fixed before release

- **MEDIUM, history rows could be converted to UTC twice.**
  - Exposure: the 1.4.5 step runs on the first request after an update, with no lock. On a busy site a second PHP worker arriving during the slow UPDATE on `wcb_job_views` also saw "not converted" and shifted every row again. Two workers converting different tables could also overwrite each other's `wcb_utc_converted` list. Silent and irreversible.
  - Fix: one site-wide `add_option()` lock (unique option name) around each conversion; others skip and keep the step pending; a lock older than 15 minutes is taken over. Tests: a held lock moves no row, a stale lock is taken over and released (both fail on the old code).
- **MEDIUM, the role repair could hand members a staff role.**
  - Exposure: the 1.4.4 repair gave every employer/candidate-only member the site's `default_role`. On a site whose default role is Author or Editor, every member gained it on update.
  - Fix (owner decision 2026-11-09): the repair skips when the default role can `edit_posts` (Contributor and up). Subscriber is still repaired, including when other plugins add capabilities to it. Tests cover both cases.

### Release hygiene found by the review

- The 1.8.3 branch was missing three commits that are in `v1.8.2` (the licence and update host change). The branch now merges master, so `v1.8.2` is an ancestor again and `wcb_licence_request()`, `WCB_LICENCE_HOST` and the 12-hour preset-activation backoff are back.

### Accepted (LOW)

- **Job form draft stays in localStorage after logout.** The key is `wcb-job-draft-{blog}-{user_id}` and the form only renders for that user, so another member on a shared browser never sees it. It holds the employer's own job text, which is meant to be public. Follow-up: clear `wcb-job-draft-*` on logout.
- **Multisite registration (old code).** `! users_can_register && ! is_multisite()` lets visitors register candidates and employers on any subsite whatever the network registration setting. Present before 1.8.3; follow-up: read `get_site_option( 'registration' )` on multisite.

### Scanner-visible but safe

- `core/class-time.php` REST ISO rewriting (`rest_request_after_callbacks`): only `/wcb/v1/` routes, skips errors, only reformats string values under `*_at` and `deadline` keys that match `Y-m-d H:i:s`; adds no field and changes no permission.
- `core/class-install.php` `migrate_deadlines_to_utc()`: prepared queries and `$wpdb->update()`; values are `DateTime` output; idempotent because it only matches date-only values.
- `core/class-locations.php` `remove_orphan_hq_links()`: core table names and the literal `wcb_location` only.
- `admin/class-setup-wizard.php` `create_jobs_menu()` / `add_menu`: route needs `wcb/manage-settings` plus the REST nonce; items are the plugin's own published page ids; an assigned menu location is never replaced.
- `admin/class-setup-wizard.php` `demo_installer_url()`: from the installed Demo Installer class, printed with `esc_url()`; no redirect.
- Dashboard tab lists in `wp_interactivity_config` and the `@wcb/ui` `timeZone` module data: hard-coded slugs and the timezone name, JSON-encoded by core.
- Decoded term names (`Taxonomy::plain()` / `names()`): every PHP sink escapes with `esc_html()`; REST and interactivity state reach the page only through `data-wp-text`.
- `Roles::save_member_roles()`: nonce `wcb_member_roles_{id}` plus `promote_user`, and it only touches `wcb_employer` / `wcb_candidate`.
