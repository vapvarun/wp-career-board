# WP Career Board 1.8.0 - Security review (Gate G)

Branch `1.8.0`, reviewed against `v1.7.2`. Pro has its own record in `wp-career-board-pro/audit/security/1.8.0.md`.
Standard: `~/.claude/skills/wp-plugin-release/references/authorization-guards.md`.

**Verdict: pass.** Every confirmed unauthorised read or write is fixed, and so is every HIGH that the lowest role can reach. The route authority test is green (82/82) and has been seen red under mutation. PHPCS, PHPStan and `composer ci:no-journeys` are all clean.

### Scanner-visible but safe

Each pattern below is flagged by the scanner but is safe, for the reason given.

**Interpolated SQL outside `prepare()`.** The 9 new hits:

- `api/endpoints/class-employers-endpoint.php:934, 982`: `SELECT COUNT(*) {$from}`. `$from` is itself built with `$wpdb->prepare()`, with placeholders for the status list and the company or user id. The page query adds only a prepared `LIMIT`/`OFFSET`. This is an improvement: 1.7.2 put the status list straight into the SQL string.
- `core/class-install.php:874`: `ALTER TABLE {$table} ADD KEY {$column}`. `$column` comes only from the two literals `'status'` and `'sent_at'` passed at `:411` and `:416`. The index is checked through a prepared `information_schema` query first.
- `import/class-wpjm-importer.php:189, 192`: read-only admin preview counts. They interpolate only core table names and hold constant literals.
- `uninstall.php:33, 43, 44, 46, 50`: set-based deletes at uninstall, guarded by `WP_UNINSTALL_PLUGIN`. They use core table names and constant, escaped `LIKE` patterns (`wcb\_%`). No request data reaches them.

**`$_FILES`, new hit `core/class-image-upload.php:52`.** `wp_check_filetype_and_ext()` checks the real file contents against a jpeg/png/webp/gif allowlist before `media_handle_upload()`, which gets the same `mimes` override. A PDF renamed `.png` is refused. The resume upload (`class-applications-endpoint.php:896`) still reads the client MIME type, but only as a first filter. `media_handle_upload()` then runs `wp_check_filetype_and_ext()` with a pdf/doc/docx override and writes into a random `wcb-private/<20 chars>/` folder with a deny-all `.htaccess`.

**`readfile()`, `core/class-private-files.php:370`.** The path comes from `get_attached_file()` for an attachment id run through `absint()`, never from the request. `can_download()` runs first, and a refusal gives the same 404 as a missing file. The filename header goes through `sanitize_file_name()`, and `nosniff` is sent. This gate also limits the handler to files this class made private (see F4).

**`esc_sql()`, `modules/jobs/class-job-search.php:410`.** The escaped values are the string keys of the `SalaryFormat::PERIOD_FACTORS` constant (`hourly`, `monthly`, `yearly`), which are scalars, and each factor is cast with `(int)`. No request data is involved.

**Pre-existing `extract-call`.** Unchanged since 1.7.2 and out of this delta.

### ABSPATH guards added

- `phpstan-buddypress-stubs.php` (the one new file) and the 9 dev scripts in `bin/` now start with `if ( ! defined( 'ABSPATH' ) && 'cli' !== PHP_SAPI ) { exit; }`.
- These files are CLI or PHPStan bootstrap files, so a plain `defined( 'ABSPATH' ) || exit` would stop them from running. None of them ship: `/bin` and the stubs file are both in `.distignore`.
- All scripts were verified to still run: PHPStan loads the stubs, and `ci:no-journeys` runs the `bin/` checks.

## G2 - Authorisation matrix as a test

- **Manifest:** `audit/route-authority.json`. It declares 68 routes, seeded from `rest_get_server()->get_routes()`. Each route is attributed to Free by reflection on its callback's file, because Free and Pro share `wcb/v1`.
- **Test:** `tests/test-route-authority.php`, run with `wp eval-file`. It is wired into `tests/run-all-tests.sh`, which also runs Pro's copy.
- **Not in `composer ci:no-journeys`:** that pipeline is static and runs without WordPress. The test needs a live site, so it runs standalone and through `run-all-tests.sh`.

The test enforces:

1. **Undeclared route fails.** A live route that the manifest does not declare fails the test.
2. **Stale entry fails.** A manifest entry with no live route fails, unless its `conditional_on` setting is off.
3. **Callback must match.** The resolved `permission_callback` must equal the declared one. Pro's `pro_check()` wrapper is unwrapped; closures are named by file. A `__return_true` route must be declared `public` with a `reason` and an `observed` signed-out dispatch.
4. **Public object routes are probed.** Every public GET route that takes an object id is dispatched signed out against a private fixture:
   - pending, draft and private jobs;
   - a draft company;
   - a private-visibility candidate.

   It must not return the fixture. A counter proves every such route was probed (4 of 4).
5. **Tripwires.** The test fails if the registry walk, the manifest or the probe set comes back empty.

The runtime matrix compares owner, a second member of the same role, and a signed-out visitor.

- Every request uses a schema-valid payload. A 400 fails the matrix, because it would prove nothing about authority.
- Refused writes are checked for side effects.
- Coverage:
  - **Applications:** read, status, notes, rating, withdraw.
  - **Per-job lists:** applicant list and CSV export.
  - **Per-candidate lists:** applications and bookmarks, including user id 0.
  - **Employer lists:** `employers/me/*` totals.
  - **Records:** job, company and candidate edits and deletes, plus the moderation bypass.
  - **Public listings:** `X-WCB-Total` for `/jobs` and `/employers/{id}/jobs`.
  - **Private files:** `can_download()` and `/files/{id}`.
- Routes that stream a file and exit (the export, `/files/{id}`) are checked through their own `permission_callback`, so an allowed actor does not end the run.

**Result: 82/82 green.**

**Mutation proof.** Each mutation was applied, run and reverted.

| Mutation | Result |
|---|---|
| `is_current_user()` accepts user 0 (the pre-fix code) | red: `/candidates/0/applications` and `/candidates/0/bookmarks` 200 to a signed-out visitor |
| `/employers/{id}/applications` set to `__return_true` | red: rule 3 mismatch, plus another employer gets 200 |
| manifest entry renamed | red: rule 1 (undeclared) and rule 2 (stale) |
| `can_download()` owner branch always true | red: 5 failures (other employer, other candidate, signed out, REST twice) |
| private-file handler serves any attachment | red: "does not serve attachments it never made private" |
| close guard removed | red: pending job closed, then published past moderation; list totals 2 instead of 1 |
| publish check back to pending/draft only | red: a trashed job published without review |
| source root pointed at `tests/` | red: tripwire (0 routes), stale entries, 0/0 probes |

## G3 - Reviewed diff (`git diff v1.7.2..HEAD`)

The review covered:

- CV and private-file delivery;
- uploads;
- the WPJM importer (no remote fetch, so no SSRF);
- REST, admin and CLI capability paths;
- guest apply;
- registration and email verification;
- GDPR;
- moderation.

### Fixed in this gate

**F1 - HIGH (pre-existing in 1.7.x). A signed-out visitor could list every guest application.**
- **Where:** `api/endpoints/class-applications-endpoint.php` (`candidate_permissions_check`).
- **Attack:** guest applications store `_wcb_candidate_id = 0`, and a signed-out caller is user 0, so `GET /wcb/v1/candidates/0/applications` returned all of them: job, status and date.
- **Same root:** the same `get_current_user_id() === $owner` comparison, with no `> 0` guard, was in:
  - `self_permissions_check` and `update_item_permissions_check` (bookmarks, saved companies and resumes, profile update for id 0);
  - the application read, withdraw and employer checks;
  - the CSV export (anyone matched a job with no author);
  - the employer company checks.
- **Fix:** one helper, `RestController::is_current_user()` (`api/class-rest-controller.php:78`), returns true only when `$owner_id > 0`. Callers:
  - `class-applications-endpoint.php:75, 1045, 1076, 1122, 1138`;
  - `class-candidates-endpoint.php:651, 665`;
  - `class-employers-endpoint.php:1188, 1276`.
- **Proof:** confirmed by dispatch before the fix (200 with the guest application listed) and red under mutation.

**F2 - HIGH (new code path in 1.8.0, bypass pre-existing). Employers could skip moderation.**
- **Where:** `api/endpoints/class-jobs-endpoint.php:759-778`.
- **Attack:** on a site that requires approval, the employer sends `PATCH /jobs/{id}` with `status=closed`, then `status=publish`. The reopen counted as a republish and went live without review. It worked from pending, draft (including rejected jobs) and trash, confirmed by dispatch.
- **Fix:**
  - Without `wcb/moderate-jobs`, only reviewed jobs (`publish`, `wcb_expired`, `wcb_closed`) can be closed; anything else gets 409 `wcb_job_not_live`.
  - Publishing any job that is not in those three statuses goes through `default_status()`, or back to review for a rejected job.
  - The employer dashboard hides Close on jobs that are not live: `blocks/employer-dashboard/view.js:438` (`isJobNotClosable`) and `render.php:738`.

**F3 - HIGH (pre-existing since 1.7.0). Registering with a guest's email took over their applications and CV.**
- **Where:** `modules/applications/class-applications-module.php` (`claim_guest_applications` on `user_register`).
- **Attack:** self-service registration signs the member in with a password they chose and does not require email verification by default. Guest applications from that email were re-owned immediately, and `can_download()` then gave the new account the guest's CV.
- **Fix:** the claim now waits until the address is proven:
  - `wcb_email_verified`, fired from `modules/account/class-email-verification.php:198`;
  - `after_password_reset`, which covers core's emailed set-password sign-up;
  - immediately, for accounts an admin or WP-CLI creates (`claim_on_register()`, `:65`).
- The new hook is documented in `docs/website/developer-guide/02-hooks-reference.md`.

**F4 - MEDIUM (new). The private-file handler streamed any attachment on the site to staff.**
- **Where:** `core/class-private-files.php:284`.
- **Attack:** `?wcb_file=<id>` and `/files/{id}` checked `can_download()`, whose staff branch (`wcb/moderate-jobs`) returns true for any id. A Board Moderator could walk ids and download every attachment, including other plugins' private files.
- **Fix:** `can_download()` now returns false unless the attachment carries `_wcb_private_file`. Moderator access to candidate files stays, consistent with moderators' pipeline access.

**F5 - MEDIUM (pre-existing). The job and company blocks rendered unpublished posts named by attribute.**
- **Where:** `blocks/job-single/render.php:28-39` and `blocks/company-profile/render.php:31-42`.
- **Attack:** an employer puts `[wcb_job_single jobid="<competitor's pending job>"]` in their own description, and every visitor sees that unpublished job.
- **Fix:** when the id comes from an attribute, the block renders only published (or ended) jobs and published companies, unless the viewer is the owner or staff. Checked with `render_block()`: signed out, a pending job renders nothing and a live job renders.
- The unused `$wcb_is_owner` in company-profile, which had the same user-0 comparison, was removed.

**F6 - MEDIUM (pre-existing). A moderator's bulk Approve published any post id.**
- **Where:** `admin/class-admin-jobs.php:701`.
- **Attack:** `?action=approve&job[]=<any id>` published pages and posts that the moderator cannot otherwise publish.
- **Fix:** the loop skips anything that is not a `wcb_job`.

**F7 - LOW (new). A banned employer could still export applicants.**
- **Fix:** the export route now requires `wcb/view-applications` alongside authorship (`class-applications-endpoint.php:75`).

### Accepted or carded (not blocking)

| Severity | Where | Finding | Why accepted |
|---|---|---|---|
| MEDIUM (pre-existing) | `blocks/job-single/render.php` (`do_shortcode` on the job description) | Employer content runs any shortcode. A self-referencing `[wcb_job_single]` recurses until memory runs out on that page. | The disclosure half is fixed by F5. Removing shortcodes from descriptions changes behaviour for existing sites. Card: gate on `unfiltered_html`, add a recursion guard. |
| LOW (new UI) | `auth/class-app-credentials.php` (`client_ip()`) | The X-Forwarded-For option trusts the leftmost address, so a client can rotate rate-limit buckets on sites that choose it. | Opt-in setting; the default is `REMOTE_ADDR`. Card: take the rightmost untrusted hop. |
| LOW (new) | `modules/account/class-email-verification.php` (`maybe_verify`) | Login CSRF: opening someone else's unused verification link signs you into their fresh account. | Low impact, and the link is single-use. |
| LOW (pre-existing) | `class-jobs-endpoint.php` (`meta__wcb_*` filter) | A yes/no oracle on private job meta, such as a flag status or apply email. | Card: replace the `_wcb_` prefix allowlist with an explicit public-key list. |
| LOW (pre-existing) | `GET /employers/{id}/jobs` | `appCount` and `appLabel` are shown to every viewer. | Counts only, no identities. Card. |
| LOW (pre-existing) | Guest apply duplicate check | "Already applied" reveals that an email applied to a job within 24 hours. | Bounded by the 10/hour per-IP limit. |
| LOW (pre-existing) | `GET /candidates/{id}` | A private profile answers 403, not 404. | The id is already public on the directory. |
| LOW (new) | `core/class-private-files.php` (`send()`) | Files are served `inline` with the stored MIME type. | Only validated PDF/DOC/DOCX and images reach the private folder, and `nosniff` is set. |

### Checked and safe

- **Resume upload:** the attachment id must be owned by the member, and guests are refused. The resume id is checked for ownership.
- **Guest apply:** 10 per hour per IP, a MySQL named lock, and the spam hook.
- **Email verification token:** 32-character CSPRNG, stored as `wp_hash`, compared with `hash_equals`, 7-day TTL, single use. The resend answers the same for unknown addresses.
- **CredentialGuard:** email or password changes require the current password.
- **GDPR:** export and erase only through core's admin-processed, email-confirmed requests.
- **CSV cells:** formula-escaped.
- **Notes and rating:** job author with `view-applications`, or admin.
- **Status changes:** limited to `employer_actionable()`.
- **Setup wizard, import, admin and industry routes:** `wcb/manage-settings`.
- **Settings endpoint:** plugin versions and licence state are blank for non-admins; the CAPTCHA secret is never exposed.
- **SEO JSON-LD:** encoded with `JSON_HEX_TAG|JSON_HEX_AMP`.
- **WPJM importer:** no remote fetch.

## Release notes (Security bullets)

```
* Security - Signed-out visitors can no longer list guest applications through the candidate applications endpoint.
* Security - Employers can no longer publish a job past moderation by closing and reopening it.
* Security - Guest applications move to a new account only after that account confirms its email address.
* Security - The private file link serves only candidate files, not other attachments.
* Security - The job and company blocks no longer show unpublished posts named in a shortcode.
* Security - Bulk Approve on the Jobs screen only acts on jobs.
```
